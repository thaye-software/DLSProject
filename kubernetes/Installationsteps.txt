Local Kubernetes setup (Windows)
================================
Goal: a local cluster we can talk to with kubectl, following kubernetes/thomasinstallguide.txt.
We do one step at a time and only mark a step done after it has been checked on this machine.

What the pieces are
-------------------
- kubectl: the command-line client. It sends requests to a cluster. It is not the cluster.
- WSL 2: Windows Subsystem for Linux. Docker Desktop on Windows runs its engine inside WSL 2.
- Docker Desktop: builds and runs containers, and can start a local Kubernetes cluster (kubeadm).
- Kubernetes cluster: the thing that actually runs pods. Docker Desktop creates it when Kubernetes is enabled.
- Lens: a free desktop app for looking at the cluster. Optional, later.

Checked on this machine (2026-11-04)
-------------------------------------
- kubectl client: v1.37.2. Current context: docker-desktop.
- cluster: running. Control plane at https://kubernetes.docker.internal:6443.
  Node docker-desktop is Ready, role control-plane, Kubernetes v1.36.1.
  Client v1.37.2 and server v1.36.1 are one minor version apart, which kubectl allows.
- docker: Docker Desktop 4.98.0 is running. Client and Server are both 29.9.2.
  Context is desktop-linux. The engine is the linux/amd64 one inside WSL.
- WSL: Ubuntu is the default distro, version 2, currently Stopped.
  Docker added its own distro, docker-desktop, version 2, and that one is Running.
  The engine lives in docker-desktop. Ubuntu staying Stopped is expected.


Step 1 — install kubectl
------------------------
Status: done.

kubectl is the client only. Installing it does not start Kubernetes.

Install (Windows, winget):
https://kubernetes.io/docs/tasks/tools/install-kubectl-windows/#install-nonstandard-package-tools

    winget install -e --id Kubernetes.kubectl

Check:

    kubectl version --client

Expected: a client version line, for example "Client Version: v1.37.2".
There is no server version yet, because there is no cluster.


Step 2 — install WSL 2
----------------------
Status: done (checked 2026-11-04).

Why this came before Docker: Docker Desktop on Windows runs its engine inside WSL 2.
The guide says: if Kubernetes in Docker Desktop does not come up, check WSL
(`wsl -v`) and update it (`wsl --update`). On this machine WSL was missing entirely,
so we installed it before Docker.

Command (needs an Administrator PowerShell, and usually a reboot):

    wsl --install -d Ubuntu

That turns on the WSL Windows features and installs Ubuntu. After reboot, Ubuntu
asks for a Linux username and password. That account is only for the Linux VM.
It is not your Windows login.

Check after reboot:

    wsl --status
    wsl -l -v

Result on this machine:
- Default Distribution: Ubuntu
- Default Version: 2
- WSL version: 3.0.1.0
- Kernel version: 6.18.40.1-1
- `wsl -l -v`: Ubuntu, VERSION 2. State "Stopped" is normal until something starts it.


Step 3 — install Docker Desktop and start the engine
----------------------------------------------------
Status: done (health check 2026-11-04).

Docker Desktop runs containers on this PC. It is also the program that will
create the local Kubernetes cluster, but that switch stays off until the engine
itself is running. Installing the app does not start the engine.

Install (Windows, winget). This downloaded Docker Desktop 4.98.0 and asked for
an administrator prompt:

    winget install -e --id Docker.DockerDesktop --accept-package-agreements --accept-source-agreements

The program is at:
    C:\Program Files\Docker\Docker\Docker Desktop.exe
The client is at:
    C:\Program Files\Docker\Docker\resources\bin\docker.exe

Checked after install, before the first launch:
    docker version
Client: 29.9.2. No Server section. The error is
"failed to connect to the docker API at npipe:////./pipe/docker_engine".
That pipe is how the client talks to the engine. It appears only after
Docker Desktop has started.

What you do now:
1. Open "Docker Desktop" from the Start menu.
2. Accept the terms on the first screen.
3. Leave the backend on WSL 2. Ubuntu is already installed, so use that distro
   if it asks which one to integrate with.
4. Wait until the whale icon is steady and the window says the engine is running.
   The first start can take a few minutes.

Check, from a new terminal (a terminal opened before install may not see `docker` on PATH):

    docker version

Health check result:
- Docker Desktop.exe found.
- docker on PATH: C:\Program Files\Docker\Docker\resources\bin\docker.exe
- Client 29.9.2, context desktop-linux.
- Server: Docker Desktop 4.98.0, Engine 29.9.2, OS/Arch linux/amd64.
- Docker Desktop process running.
- WSL: Ubuntu Stopped (version 2), docker-desktop Running (version 2).

The Server section means the engine is up. Docker Desktop runs that engine in its
own WSL distro, named docker-desktop, not in Ubuntu. Ubuntu can stay Stopped.


Step 4 — enable Kubernetes in Docker Desktop
---------------------------------------------
Status: done (checked 2026-11-04).

The engine can run containers. It is not a Kubernetes cluster until this switch
is on. Docker Desktop then builds a one-node cluster with kubeadm, which is the
option named in kubernetes/thomasinstallguide.txt. The cluster runs inside the
same docker-desktop WSL distro. kubectl, already installed, will talk to it.

In Docker Desktop:
1. Open Settings (the gear).
2. Open Kubernetes.
3. Tick Enable Kubernetes.
4. If the page offers a choice of cluster type, choose kubeadm.
5. Click Apply & restart.
6. Wait until the Kubernetes status is green / "running". The first time downloads
   cluster images and can take several minutes. Leave Docker Desktop open.

Then, in a terminal:

    kubectl config current-context
    kubectl cluster-info
    kubectl get nodes

Result on this machine:
- current context: docker-desktop
- control plane: https://kubernetes.docker.internal:6443
- CoreDNS is running in namespace kube-system
- node docker-desktop: Ready, role control-plane, age about 108s at first check, version v1.36.1

kubectl on this PC is v1.37.2. The cluster is v1.36.1. One minor version of
difference is normal and supported. Docker Desktop chooses the cluster version.
We do not need to downgrade kubectl.


Step 5 — install Lens
---------------------

Lens is a desktop app that shows the same cluster kubectl talks to: nodes, pods,
logs, and YAML. It is optional. The cluster already works without it. The guide
asks for the free version: https://lenshq.io/

Install it from that site (or the Lens installer it offers for Windows), sign in
with the free account if it asks, then add the local cluster. Docker Desktop
usually appears on its own as context docker-desktop, because Lens reads the
same kubeconfig file kubectl uses (C:\Users\[USER]\.kube\config).

Check: Lens shows the docker-desktop cluster, and the node docker-desktop is Ready.
That is the same node `kubectl get nodes` already printed.


After Lens is installed, you should set it up:
in the first dialogue box,
"Step 1 Kubenetes environments"
you should do nothing. We run kubernetes locally, so we dont need any clouds.

in this step:
"step 2 local kubeconfigs"
Click Watch files.
out cluster should be stored in one file, not in a folder of configs. Point Lens at:
     C:\Users\[USER]\.kube\config

"step 3 Ai tool"
use your tool of choice or NO AI.

"step 4 AI tool access"
Leave both toggle switches off and continue.

skip and continue
